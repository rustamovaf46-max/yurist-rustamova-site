## 1. Запрос в Google Gemini — независимый аудит Google
Скопировать целиком в Gemini (лучше с веб-доступом):

> Действуй как независимый технический SEO-аудитор. Проверь **самостоятельно** https://юриструстамова.рф/, публичные /sitemap.xml и /robots.txt, главную, три страницы судебных услуг, библиотеку и выборку из десяти разных юридических статей; если сайт недоступен из твоей среды, прямо сообщи. Не делай вид, что тебе доступны чужие Search Console, реальные Core Web Vitals или данные о позиции. Сопоставь наблюдения с официальной Google Search Central. Проанализируй: индексационные препятствия, canonical и зеркала, внутренние ссылки с информационных материалов на услуги, качество/оригинальность юридического контента (YMYL), опыт и доказанное авторство, мобильный UX, изображения, скорость и варианты честной структурированной разметки. Раздели **проверенные факты / гипотезы / ложные или рискованные советы**. Дай не более десяти изменений по убыванию вероятной пользы для **судебных обращений**, а не просто просмотров. Для каждого укажи точный URL, фактическое подтверждение (или что нужно измерить), корректирующее действие, возможный риск и способ проверить успех через GSC за 14–28 дней. Не предлагай 100 однотипных страниц, накрутку, фиктивные кейсы, гарантию попадания в индекс или ложные FAQ-расширения. Заверши пятью уточняющими вопросами **к данным**, а не к владельцу сайта.

## 3. Как ЗЕВС использует ответы
1. Получить два независимых отчёта на одинаковый срез сайта, сохранив дату, модель, URL и доступные ссылки на доказательства. **Не давать одной модели ответ другой до первичной проверки**.
2. Проверить каждое предложение по коду GitHub, живому REG.RU, данным GSC Wizard/Яндекс Вебмастера и официальной документации; расходящиеся гипотезы выделять отдельно.
3. Внедрить только подтверждённые и разрешённые бесплатные изменения; отдельные PR/коммиты, тесты, HTTP 200 и проверка деплоя. Не менять судебные ссылки без первоисточников.
4. Через 14–28 дней сравнить поисковые показы, небрендовые запросы, проиндексированные URL, лиды и качество обращений. Выводы ИИ не являются подтверждением индексации.

## 4. Следующий технический этап: без ключей и платных запросов
- Разработать защищённый **read-only шлюз / частный плагин ЗЕВС** с инструментами `review_gemini_public_seo`, `review_alice_public_seo` и `compare_independent_reports`. Пока аккаунты не подключены, инструменты не должны изображать реальные ответы моделей.
- Gemini API потребует отдельный ключ Google AI Studio с подтверждением доступности бесплатной квоты. Alice AI LLM потребует сервисный аккаунт/ключ Yandex Cloud и проверенный биллинг; существующий токен Яндекс Вебмастера здесь непригоден.
- Ключи размещать только в приватных секретах сервера/CI; **не в HTML, JS, README, Issues, чатах или GitHub-коммитах**.
- Запуск по умолчанию выключен. Любая тарифицируемая операция — только после отдельного согласия. Никаких клиентских документов, только публичные страницы.
- После подключения обеих моделей организовать регулярное независимое рецензирование важных новых страниц, **но не допускать автоматической публикации только потому, что модель «одобрила» текст**.
