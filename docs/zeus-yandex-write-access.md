# ЗЕВС — отдельное управление Яндекс Вебмастером

Созданный компонент использует **официальный Яндекс Вебмастер API v4** и уже включён в существующий репозиторий сайта `юриструстамова.рф`. Новый сайт не создаётся; REG.RU и действующий скрипт публикации не меняются.

## Что работает после авторизации

- Каждый час GitHub Actions проверяет подлинный Яндекс UID, отдельные HTTP и HTTPS записи нашего домена, статусы подтверждения прав, главное зеркало и причины отказа.
- По разрешённой команде Зевса, зафиксированной в `.github/zeus-yandex-command.json`, GitHub Actions может выполнить подтверждение HTTPS-ресурса **только после проверки существующего файла доказательства** и отправить изменённые HTTPS-адреса на переобход.
- Команда работает на серверах GitHub без включённого ноутбука. API-токен остаётся скрытым в GitHub Actions Secret; он никогда не записывается в код, сообщения, логи или HTML.
- Действия удаления сайта, смены DNS/зеркала, произвольные внешние адреса, платные операции **не реализованы**.

## Одно обязательное действие владельца

Яндекс не позволяет получить OAuth-токен за владельца без его согласия.

1. Открыть официальную инструкцию Яндекса: https://yandex.ru/dev/webmaster/doc/ru/tasks/how-to-get-oauth . Под **тем Яндекс ID, где виден подтверждённый HTTPS-сайт**, создать собственное OAuth-приложение с правами `webmaster:hostinfo` и `webmaster:verify`. По официальной документации токен действует **шесть месяцев**, поэтому его нужно будет своевременно обновлять.
2. В GitHub открыть репозиторий `rustamovaf46-max/yurist-rustamova-site` → **Settings → Secrets and variables → Actions → New repository secret**. Название: `YANDEX_WEBMASTER_TOKEN`; значение: полученный токен. **Не присылать токен в чат или скриншотом.**
3. В GitHub **Actions → ZEUS Yandex Webmaster owner API → Run workflow → audit** проверить результат. Если вывод показывает HTTPS и `verified: true`, интеграция готова для управления. Если там только HTTP или `verified:false`, дальше Зевс выявит проблему по `verification_state` и `failure_reason`.

## Команды из ChatGPT через GitHub

Подключённому GitHub уже разрешены действия записи. После добавления секрета Зевс меняет только файл `.github/zeus-yandex-command.json`, чтобы запустить разрешённую операцию:

- `{"operation":"audit","urls":[]}` — проверка;
- `{"operation":"recrawl","urls":["https://xn--80aafwvmkbibjcl2m.xn--p1ai/страница.html"]}` — переобход конкретного изменённого URL (до 10 URL);
- `{"operation":"verify","urls":[]}` — запуск подтверждения **только** при успешной проверке файла `yandex_<текущий-код>.html`.

Каждое изменение команды должно быть отдельным коммитом; повторные сохранения без новых изменений не запускают workflow. Результат см. в GitHub Actions. Выполнение переобхода означает принятие заявки роботом, **не** включение страницы в поиск.

## Ограничения

Это автономная связка **GitHub Actions → Яндекс API**, а не отдельный подключённый MCP-сервер ChatGPT. Прямой доступ к Яндекс API по существующему GSC Wizard остаётся только для чтения. Для полноценного MCP в ChatGPT потребуются доступный защищённый MCP-хостинг и OAuth владельца; они не предоставляются созданием файлов. До добавления секрета этот workflow только сообщает о том, что авторизация ожидается.

Документация: https://yandex.ru/dev/webmaster/doc/ru/concepts/getting-started
