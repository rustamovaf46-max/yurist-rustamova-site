# Многоязычная индексация: проверяемые правила

Цель — рост релевантного поискового трафика и судебных обращений, а не искусственное увеличение числа URL.

## Что уже реализовано

- Четыре языковые версии материала об электронных доказательствах: RU, EN, ZH, AR.
- Самостоятельные URL и canonical каждой языковой версии.
- Взаимные hreflang + x-default и видимый переключатель языков.
- Поддержка папок en/zh/ar в scripts/reg-ru-deploy.sh.

## Критерии публикации следующей статьи

1. У каждой версии собственный корректный `lang`, уникальные title и description; арабский — `dir=rtl`.
2. Перевод должен передавать российские правовые институты без подмены иностранными аналогами; полезные различия объяснять, а не просто переводить термины.
3. Не публиковать языковую страницу с тонким, шаблонным, невычитанным или повторяющимся текстом.
4. Canonical ведёт на себя; hreflang перечисляет все реально существующие и доступные по HTTP 200 версии.
5. В sitemap добавлять только URL, доступные по HTTP 200 и без noindex. При задержке REG.RU проверять повторно после cron.
6. Ссылки из материала вести на тематические услуги и другие полезные статьи, без искусственных анкоров.
7. Новая русская статья считается одной редакционной публикацией; её переводы не засчитываются как дополнительные ежедневные статьи.
8. Проверять фактическую публикацию на REG.RU, а не только наличие в GitHub.

## Измерение результата

- По каждому языку: число индексируемых/проиндексированных URL, показы, клики, CTR, поисковые запросы и обращения в MAX/по телефону.
- Сравнивать по 28-дневным периодам, не обещать позиции и не считать смену даты улучшением качества.
- Яндекс Вебмастер и Google Search Console — источники данных по индексации; Метрика — события и обращения при соблюдении согласия пользователя.
- Переводить в первую очередь страницы с подтверждённым спросом и качественным русским оригиналом.

## Технические риски

- Публикация вложенных файлов может потребовать создания каталогов на REG.RU; скрипт это делает через publish_file.
- Проверка живых статей должна использовать полный относительный путь, а не только basename.
- Точное равенство байтов подтверждается прямым HTTP сравнением; HTML, обработанный краулером, не подходит для побайтовой сверки.
- Наличие hreflang не гарантирует индексацию или высокую позицию.
